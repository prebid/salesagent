Constraint compiler for the adcp type generator

Solution design · adcp-client-python at 9.0.0b2 · schema pin ADCP_VERSION 3.2.1 (bundle schemas/cache/3.2, 1509 non-bundled files) · generator datamodel-code-generator==0.64.0, pinned indefinitely · measured against upstream main 0c7e8b86d

The defect class: the generation pipeline reads a schema root's constraint content partially, and drops the rest without a trace. Each dropped keyword is a document the published model accepts and the canonical schema refuses. The fix: one reader for that content, with a closed grammar; every keyword kind it knows compiles into the model as ordinary Python; any keyword it does not know aborts generation, naming the file, the JSON pointer and the keyword. After this design, a dropped keyword has no spelling: a schema either generates a model that enforces all of its root constraints, or it does not generate at all.

1 · What exists today: three partial readers of one kind of node

A schema root's constraint content — a root anyOf/oneOf whose arms are overlay constraints, a root if/then/else, root dependencies, a root not — is dropped by datamodel-code-generator 0.64.0, which renders the merged properties and nothing else. The repo's own repair layer reads that content in three places, each taking what it can carry:

A refusal lane exists — enforce_root_required_groups prints a skipped reason for 97 schemas it declines wholesale — but there is no refusal for a keyword dropped inside an arm it does emit for. That asymmetry is the hole: the pass succeeds, the module ships, and the model is weaker than its schema with nothing anywhere saying so.

What the hand-patch proved

Experiment commit 0537063a2 (branch experiment/handpatch-arm-conditions) hand-expanded all three create_media_buy arms — each arm's not, its budget_allocation.mode const, and arm 0's per-package budget-required and min_spend_target-forbidden item conditions — as ordinary Python over model_fields_set and attribute reads. All nine differential parity cases pass. On cost, the before/after delta from the experiment is contaminated (its baseline leg raced another measurement over the same file) and is not cited here; what is solid, measured twice and under load, is the absolute: the patched model validates in 4.1–6.9µs total, while the schema-delegation alternative was measured at +64µs on top of a 9–102µs baseline — the entire patched validation costs roughly a tenth of what the alternative merely adds. “Inexpressible in pydantic” is false. The emission target is cheap, readable Python; what is missing is only the machine that writes it.

The census's most important finding: six keyword kinds the hand-patch never met appear at the pin and are inside this design's scope: not in its {properties, required} form (12 arms — creative/preview-creative-response.json: “status must not be submitted”), a nested oneOf inside an arm (media-buy/get-reporting-status-response.json, both arms — unread by any current pass even though that module carries the required-group validator), arm-level if/then (media-buy/build-creative-response.json oneOf[2]: “if vendor_cost is supplied then currency is required and every variant carries four fields”), root dependencies/dependentRequired (27 files, including the get-signals ledger entry), contains (1), and propertyNames (1). All six are expressible in the same vocabulary the hand-patch used. A design covering only the hand-patch's four kinds would have shipped with holes in its first release; this one's grammar is sized by the census, and its closure rule (§3.3) is what keeps the next bundle's new kind from becoming a hole.

Reconciliation with the file-level histogram measured independently on the same 42-module population (12 of 42 modules have arms with discarded constraining keywords; by top-level arm keyword: not 8 files, properties 6, oneOf 1): consistent with the occurrence counts above — that histogram reads each arm's top-level keys only and leaves the layer nested under properties open, while the counts in this section come from a recursive walk of every arm, so the nested layer is measured, not assumed. Going forward the guarantee rests on neither measurement: the bundle-closure test (§4, commit 1) re-derives the full accounting on every run.

Deliberately outside the defect class (already rendered correctly by existing machinery): root allOf as inheritance (519 files), unions whose arms are standalone types (the generator renders per-arm classes or scalar Annotated types — core/macro-bearing-url.json's pattern arms are already constrained scalar classes), and field-level annotations the Emitter already expresses (type, format, bounds, minItems on a field's own declaration).

3 · The design

3.1 · One reading of a schema node

New module scripts/schema_constraints.py. It is the only code that reads root constraint content; the two partial extractors are deleted in the commits that wire it (§4). It produces one structured record per schema root:

@dataclass(frozen=True)
class Arm:
    pointer: str                              # "anyOf/0" — provenance, never identity
    title: str | None                         # identity source 1
    discriminator: tuple[str, str] | None     # identity source 2: (property, const)
    required: tuple[str, ...]                 # identity source 3, and a constraint
    declares_fields: bool                     # properties introducing new fields → class-creating arm
    condition: Cond                           # the WHOLE arm as one constraint tree

@dataclass(frozen=True)
class RootConstraints:
    combinator: Literal["anyOf", "oneOf"] | None
    arms: tuple[Arm, ...]
    conjuncts: tuple[Cond, ...]   # root if/then/else, dependencies, dependentRequired,
                                  # root not, and constraint arms of a root allOf

def read_root_constraints(schema: dict, declared: DeclaredShape) -> RootConstraints: ...

Three consumers, all taking the same record and nothing else from the node:

  • the validator pass (replacing enforce_root_required_groups) compiles arms[*].condition and conjuncts into the root class's model validator;
  • the Emitter takes field shapes from properties as today, arm identity from the record, and compiles each arm's constraint residue (what its class structure does not already carry) into that arm class's own validator;
  • the naming rule (scripts/union_arm_names.py, designed and measured under #1409) takes title / discriminator / required and the class-creating classification from the same record.

Cond is a closed grammar of about fifteen node kinds, sized by the census:

Supplied(name)                      # required: the caller sent the field (model_fields_set)
Not(c) · AllOf(cs) · AnyOf(cs) · OneOf(cs) · IfThen(if_, then, else_)
PropSatisfies(name, c)              # descend into a supplied value; vacuously true when absent
ValueConst(v) · ValueEnum(vs) · ValueType(t) · ValuePattern(p)
ValueLen(min, max) · ValueBounds(ge, le, gt, lt) · ValueItems(min, max) · ValueUnique()
EveryItem(c) · SomeItem(c)          # items / contains
KeysSatisfy(c) · PropCount(min, max)   # propertyNames / minProperties, maxProperties
DependentRequired(name, names)      # dependencies, dependentRequired
Restated()                          # a keyword proven identical to the declaration (§3.3)

3.2 · Emission: every keyword kind it knows, as the hand-patch wrote it

A small hand-written vocabulary module, src/adcp/types/_conditions.py (≈10 primitives, a few lines each, unit-tested once: supplied, const_is, every_item, none_of, …). The generator emits compositions of those primitives — one @model_validator(mode='after') per flat root, one per arm class — so the emitted code reads like the experiment commit, which is the explicit target shape:

# compiled from media-buy/create-media-buy-request.json anyOf — titles from the arms themselves
explicit_packages_with_fixed_allocation = (
    'packages' in supplied
    and 'proposal_id' not in supplied
    and _c.const_is(self, 'budget_allocation', 'mode', 'fixed', vacuous=True)
    and all(
        'budget' in p.model_fields_set and 'min_spend_target' not in p.model_fields_set
        for p in self.packages or ()
    )
)
  • required → model_fields_set membership. The hand-patch's documented convention is kept: an explicit null is supplied (on a mutation input it is the command to clear); a default the caller never sent is not. The presence guard is membership, never is None — measured: an is None guard is only correct when the field's default happens to be None; a non-None default makes it false for an absent field and the check over-refuses, while unguarded attribute access raises on absence and explicit null alike.
  • not, all three measured forms: {required: [...]} → absence; {anyOf: [...]} → not any(...); {properties, required} → negated conjunction of presence and the property predicate (“not (status supplied and status == 'submitted')”).
  • Property const/enum, including through nested properties/required chains → attribute comparison, vacuous when the carrying object was not supplied or is an explicit null (JSON Schema properties grades present object members only). The descent short-circuits on the nested instance's own model_fields_set ('mode' in self.budget_allocation.model_fields_set), which is what keeps the const case mechanical: the emitter never needs to statically resolve a nested annotation like budget_allocation's discriminated union alias at runtime.
  • Nested allOf over array items → all(...) over the list, with a $ref arm admitted only as a proven restatement (§3.3).
  • if/then/else → implication; dependencies / dependentRequired → implication over presence; contains / propertyNames / min/maxProperties / uniqueItems / value bounds / patterns → the obvious one-line predicates.

Wire aliases. model_fields_set holds field names, not wire names (measured: a field aliased schema appears as schema_), so every schema-named property in a compiled predicate passes through a wire→field map before emission. The map comes from the imported staged class's model_fields — FieldInfo.alias carries it — which is the second reason §3.2 resolves classes by import rather than by AST. Where a nested annotation is a union alias, the map is taken from the union's members, and members that disagree on a constrained name refuse; nothing is skipped and nothing guessed. (No field in the arms measured at the pin is aliased, so this path is a precondition proof, not a live rewrite.)

Why a recursive compiler and not a flat rule table. The contains case (control-media-buy-request's root allOf, under if {required:[bidding]}) needs a per-element predicate over a path two hops deep (goal.target.kind), and each hop needs its own vacuity decision — the second hop is past where the runtime model_fields_set short-circuit alone can carry it, because emitting the hop requires the first hop's type. Import-based resolution supplies that type at generation time, and the Cond tree composes the per-hop guards the same way at every depth. A flat table of arm-shape rules bottoms out exactly here; the recursive grammar does not.

Combinator semantics. anyOf → at least one arm's full predicate holds. oneOf on a flat root → exactly one — derivable now, because predicates are complete; the old pass's docstring was right that cardinality is not derivable from required alone, and that reason dissolves with the partial reading. The parser refuses to compile exactly-one for a oneOf whose arm carries a declared-behavioral key (§3.3) — measured zero such arms in population A at the pin — so cardinality is never silently approximated. For union-rendered responses, arm membership is pydantic's union validation; each arm class enforces its own residue, and cross-arm exclusivity stays with wire validation (§6).

Where a validator lands. The pass resolves the class and its field set by importing the staged module and reading model_fields — the same way consolidate_exports.py already imports the staging tree — replacing the AST base-walker whose unresolved-base failures are two of today's skip reasons. It runs after rewrite_scalar_rootmodels (last substantive fix, so classes are final) and before the import-hygiene passes (it adds imports), honoring the ordering contract documented in docs/design/type-generation.md. A constraint naming a field that exists on no class for that schema is a refusal, not a skip — that is a generator field-drop surfacing loudly.

Error messages are a contract surface. Two tests match on the emitted wording (tests/test_codegen_contract_compatibility.py:297 and :322, both match="at least one of these field groups"), so a generator that changes the text breaks tests regardless of behavior — the experiment already tripped this. The emitted message therefore keeps the "at least one of these field groups" prefix and names the arms by their schema titles (“… field groups: Explicit packages with fixed allocation | …”) — schema-derived text, not authored, and more readable than synthesized field lists. This is the one place the series could break tests for a non-behavioral reason, and this sentence is what prevents it.

Cost. Compiled Python, no runtime schema walking: the hand-patch measured the whole approach at noise level (§1). The vocabulary module adds no import weight beyond what generated modules already carry.

3.3 · Refusal: the closure rule

Parsing is key-consuming. For every node it visits, the parser must account for every key as exactly one of:

  1. Compiled — consumed by a grammar production above.
  2. Annotation — a named frozen set: title, description, deprecated, examples, $comment, default, x-entity, x-status, x-deprecated-in, x-removed-in. These carry no validation semantics by JSON Schema's own definition.
  3. Declared behavioral — exactly {x-adcp-validation}. docs/validation-contract.md already states these rules are outside the structural models' promise and are carried by canonical wire validation plus targeted hand-written validators (e.g. MediaBuyChangeTerm). The parser records the classification on the record (so oneOf cardinality can refuse, above); it is a contract citation, not a tolerance entry — there is no per-schema list.
  4. Proven restatement — type, $ref, format, or a property re-declaration inside constraint content compiles to Restated() only when it resolves equal to what the generated class already declares for that position (same resolved $ref target, same type). create-media-buy-request's packages.items.allOf[0].$ref to package-request.json is the worked case. A narrowing compiles as a value predicate when the grammar expresses it; equality is checked, never assumed.

Any other key raises UnexpressibleKeywordError(schema_file, json_pointer, keyword) and generation aborts before install — generate_types.py's staging-and-rollback semantics already guarantee the checkout stays clean. There is no list of known-dropped keywords anywhere in the design. A keyword is compiled, classified by a named rule, or fatal. That is what makes the defect unconstructible rather than detected: a schema whose constraint content the SDK cannot express cannot produce a shipped model, so the state “model weaker than its schema, silently” has no code path that reaches a release. Growing the grammar when a future bundle introduces a new kind is one Cond node, one compiler case, one constructed-node test — and until that lands, regeneration is red, not quiet.

The old pass's skipped print lane is deleted with the pass. Its three reasons dissolve: “inherits an unresolved base” (import-based field resolution), “no single root model class” (the per-arm lane carries those), “not one flat model over the groups” (the constraint lands on the arm class that declares the fields). What cannot be placed refuses.

3.4 · Identity derived from the node

The naming defect is the same node read by its position instead of its content. scripts/union_arm_names.py already exists, designed and measured under #1409 (branch claude/issue-1409-union-arm-naming): classify first (an arm adding no new property is a validation constraint and creates no class; bare $ref and scalar arms create none either), then name a class-creating arm by the first unique source among its title, the parent name plus its discriminator const, or the parent name plus its full sorted required set — and otherwise refuse (UnnameableArmError), never number. Measured on the pinned bundle: 557 root-level non-null arms — 169 named by title, 82 by const, 27 by required set, 278 creating no class, 1 refused. This design wires it: the class_names comprehension at post_generate_fixes.py:5483 and the BuildCreativeResponse permutation at :5478 are deleted, and the Emitter takes names from the shared Arm record (§3.1) — the identity and the constraint now come from one reading.

The arm with no title (content-standards/get-content-standards-response.json oneOf[0]; no title, no discriminator const, no required set — upstream title filed as adcontextprotocol/adcp#7913): the rule stays total instead of gaining a fallback. The repo's refusal list already draws the line — “numbered classes may remain as module-internal helpers reached only through a field annotation, where the name is cosmetic; a public binding is the contract”. So: a nameable arm gets its public binding; an unnameable class-creating arm is emitted module-internal (underscore-prefixed, excluded from __all__, the domain namespace and the flat surface), reachable through the union alias that is how unions are consumed anyway. No ledger records this: it is the rule's total mapping, and the day the upstream title reaches the pin, the public binding appears with no repo change. Positional, invented-semantic, and cache-edited names are all refused.

Helper names do not reintroduce positional naming one level down. The hand-patch named two helpers by hand; the mechanical emitter names none. Per-arm predicates are expressions inside the one validator (an anyOf needs no named parts), locals are named by the field they test (node-derived), and everything reusable lives in the hand-written vocabulary module with fixed names. The only names the generator mints are class names, and those come from the identity rule above.

The 40 digit-suffixed public names (count: distinct \w+\d strings quoted in src/adcp/types/__init__.py; docs/design/type-generation.md counts 38 on the flat surface) become renames. 9.0.0 is in beta (9.0.0b2) — the breaking window is open now, which is the whole reason to land this series inside it. The rename table goes in MIGRATION_v8_to_v9.md; semantic aliases in src/adcp/types/aliases.py re-point as they did under PR #1374's renumbering measurement; no deprecation shim, because a shim for a name that was an ordinal pins the ordinal's meaning one release longer.

3.5 · Precedent

The shape of this fix matches the one already accepted as structural for the redeclaration defect (CanonicalBoundaryModel.__pydantic_init_subclass__, branch fix/canonical-redeclaration-keeps-its-constraints at 99b7e327c): derive the correct artifact from the one source at construction time, so the wrong artifact is never built — instead of checking the built artifact afterwards. Here the source is the schema node, the construction is generation, and the derivation either completes or refuses.

5 · What becomes impossible, what remains detected

DefectAfter this designBy what mechanism
A constraint keyword inside root constraint content dropped silently Impossible The closure rule: every key is compiled, named annotation, declared behavioral, or proven restatement — or generation aborts naming file, pointer, keyword. There is no shipped-but-weaker state to reach.
Two call sites reading one node divergently (validator vs Emitter vs naming) Impossible One reader produces one record; the partial extractors are deleted, so a second divergent reading has nothing to call.
A validator checking less than its arm states Impossible The validator is compiled from the same Cond tree the closure rule accounted for; the required-names-only extraction path no longer exists.
A positional name on the public surface; an arm's public name moving when upstream reorders arms Impossible Public bindings derive from node identity (title / const / required set) and the numbering path plus the hand-reorder are deleted; an unnameable arm yields no public binding rather than a number.
A new keyword kind in a future bundle quietly widening the models Impossible Regeneration refuses until the grammar grows by a reviewed node + test. (The cost is a red regeneration; see §6.)
x-adcp-validation behavioral rules Remains detected Declared outside the structural models' promise by docs/validation-contract.md; carried by canonical wire validation and targeted hand validators; the parity suite detects regressions. This is a scope contract, cited by the parser — not a per-schema tolerance list.
oneOf exclusivity across union-rendered response arms Remains detected Pydantic union validation picks an arm; each arm enforces its own residue; cross-arm exactly-one stays with canonical wire validation. Flat-root oneOf, by contrast, becomes enforced exactly-one.
Field-level format semantics pydantic lacks (e.g. uri-template → str) Remains detected A pre-existing type-level looseness outside this defect class; wire validation carries it. Named here so the coverage claim is not read as total.
The differential parity corpus itself Remains detected (by design) Finite hand-added fixtures stay as detection in depth. The structural guarantee is the parser's refusal; the corpus is the independent witness that it holds on real documents.

6 · The strongest argument against this design

It makes generated request models stricter, and it makes regeneration brittle on purpose. Every adopter who constructs a CreateMediaBuyRequest that names a proposal_id alongside packages, or a package without a budget under fixed allocation, parses fine on 8.x and raises on 9.0 — including test fixtures and incremental builders that fill fields after construction. And the closure rule means any future bundle sync that introduces one new keyword anywhere in root constraint content turns regeneration red until someone grows the grammar: the SDK's refresh cadence is now coupled to upstream schema authors' keyword choices.

The answer, in both halves. The strictness is the protocol's: every document these validators refuse is a document canonical wire validation already refuses, so the adopters who break were shipping requests sellers reject — 9.0.0 is in beta precisely so this class of correction lands inside an already-breaking major, and the repo's own validation contract already points adopters who need laxity at model_construct and the ValidationHookConfig escape hatches. The brittleness is the design: the previous behavior — regeneration always green, models quietly weaker — is the defect this document exists to end, and the red state is cheap to exit (one grammar node, one compiler case, one test) and impossible to ignore. What would genuinely weigh against shipping is a mismatch between a compiled predicate's semantics and JSON Schema's on some corner (e.g. properties grading only present members, nulls under required); the suppliedness conventions in §3.2 pin those corners, the vocabulary tests grade them one by one, and the parity corpus checks the composition against the canonical validator on real documents — the one place a semantic slip would land first.
