# Release 3.0.0 — upgrading from 2.x

3.0.0 is a major release. No single commit was marked breaking, but taken together the changes since
2.0.0 break existing deployments and buyers in the ways below. **Read the first section before you
deploy:** several migrations stop the upgrade, by design, until data or configuration is fixed, and
migrations run when the container starts.

Change records for each PR, in the format of [2.0.0](2.0.0.md), are still to be written. The full
commit-level list is in [`CHANGELOG.md`](../../CHANGELOG.md).

## Before you upgrade: migrations that refuse to run

Each of these checks the database and, if it finds something it cannot fix safely on its own, stops
with a message naming the rows. The upgrade then needs the data corrected and the migration re-run.
Check for these before deploying, so the upgrade doesn't stop on startup.

| Migration | Stops when | What to do |
| --- | --- | --- |
| `7f31c0ab94d2` virtual_host is mandatory | A tenant has no `virtual_host`; a `virtual_host` is not a bare `host[:port]` (a URL, a path, `user@host`, whitespace); or two tenants claim the same host name (case and port ignored) | Set each tenant's `virtual_host` to the host that deployment really answers at; resolve duplicates |
| `9b2d4f6c1a37` normalize legacy media buy status | `media_buys.status` holds a value outside the closed status vocabulary (after case normalization) | Decide each listed buy's status and correct the rows |
| `b4f1a9c27d53` creatives format_kind not null | A creative's format reference has no canonical projection | Change each listed creative's `agent_url`, `format` and `format_parameters` to a format that projects, or delete it |
| `e2af0c242a7f` publishers own their adagents document | A product selects publishers by legacy property tags or ids that match no authorized property of its tenant | Add the authorized properties those selections mean, or give each product explicit publisher selectors in the admin UI |
| `d8b2f4a6c1e3` move legacy gemini key into ai_config | A tenant's legacy `gemini_api_key` doesn't decrypt with the deployment's `ENCRYPTION_KEY` | Set the `ENCRYPTION_KEY` the keys were written with, or clear or re-enter those tenants' AI settings |
| `9fdf18a56063` encrypt the GAM refresh token at rest | GAM OAuth refresh tokens are stored and no usable `ENCRYPTION_KEY` is set, or a stored token was encrypted with a different key | Set `ENCRYPTION_KEY` (see below); for a different key, set the one the tokens were written with, or clear and re-enter those tenants' GAM credentials |

## Configuration

- **`ENCRYPTION_KEY` is required for tenants that use GAM OAuth (refresh-token) credentials.** The
  refresh token is now encrypted at rest, like the service account JSON. Use the key the deployment
  already uses for its other secrets, if it has one. See
  [environment variables](../deployment/environment-variables.md).
- **Behind a reverse proxy, pass `X-Forwarded-Proto` and `X-Forwarded-Host`.** The admin UI now
  refuses cross-origin state-changing requests. Current browsers are judged by `Sec-Fetch-Site`,
  which doesn't depend on the proxy; for a browser that sends only `Origin`, the comparison uses
  the request's own scheme and host, so without those headers it fails closed. See
  [cross-site request forgery](../security.md#cross-site-request-forgery).

## Behavior changes

- **Admin UI session cookie** is `SameSite=Lax` and `HttpOnly` in production (it was `SameSite=None`,
  readable by scripts). The admin UI can no longer be used inside a frame on another site, and a
  form on another site can no longer post to it.
- **The stored GAM refresh token is never sent to the settings page.** Detect network, test
  connection and configure use the stored token when the page sends a blank one (OAuth tenants only).
- **Publishers and their properties** come from each publisher's `adagents.json`:
  `publisher_partners` becomes `publishers`, and `authorized_properties` is dropped. Every publisher
  starts "never fetched", so expect products to lack properties until those documents are fetched.
  ([#2330](https://github.com/prebid/salesagent/pull/2330))
- **The tenant's own format catalog is removed;** the agent no longer publishes `formats[]` in its
  `adagents.json`. Format options belong to each publisher's document.
- **The mock adapter's `dry_run` option is removed.**

## Changes buyers see

- **AdCP 3.2 canonical format model, adcp 9.x**
  ([#2474](https://github.com/prebid/salesagent/pull/2474)): creatives, products and inventory
  profiles carry canonical format identities.
- **One error-code table for every buyer-facing error**, and the AdCP 3.1.1 capabilities and accounts
  contract ([#1721](https://github.com/prebid/salesagent/pull/1721)).
- **Delivery and media buy status:** `completed_views` rename and the media-buy status taxonomy
  ([#1545](https://github.com/prebid/salesagent/pull/1545)).
- **A2A:** an unknown task id returns `TaskNotFoundError` (-32001)
  ([#1648](https://github.com/prebid/salesagent/pull/1648)), skill names are validated, and returned
  tasks are registered ([#2457](https://github.com/prebid/salesagent/pull/2457)).
- **MCP tool input schemas** are published with their `$defs` and `$ref` intact
  ([#2411](https://github.com/prebid/salesagent/pull/2411)).

## Security

3.0.0 fixes [GHSA-jfcg-v466-cp2j](https://github.com/prebid/salesagent/security/advisories/GHSA-jfcg-v466-cp2j)
(CSRF in the admin UI, and exposure of the stored GAM refresh token). There is no fix for 2.x.
