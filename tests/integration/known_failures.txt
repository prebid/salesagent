# WHY THESE ARE LEDGERED RATHER THAN FIXED OR DELETED. Production has one path to every
# implementation: a transport hands ``serve`` the raw payload and the request headers, the
# resolver builds the identity once, and the tool reads typed models. Nothing downstream of
# the boundary needs a dict. The integration testing layer is the only thing still shaped
# the old way — it injects identities through the wire, mocks our own collaborators, reads
# envelopes as raw dicts, seeds tenants partially, and asserts on statuses it set up

# still the wrong unit of work, because the layer is what is wrong. Each block below names
# the child issue that owns its rewrite.
#
# Per tests/CLAUDE.md the order is BDD, then integration only if BDD genuinely cannot, then
# unit only for a pure function. Most of what is listed here grades buyer-visible behaviour
# — a response field, an error code, a status, a webhook — which is BDD's, on all four
# transports against real production. A scenario REPLACES such a test; it does not port it.
